Performance and code quality

When you detect an avoidable performance problem, fix its root cause during the current task whenever it is in scope and safe. Do not knowingly leave a performance anti-pattern as an unspecified follow-up. If an immediate fix is not safe or not in scope, record the exact blocker and the affected path.

Use performance inefficiency or performance problem as the umbrella term. Use performance anti-pattern for a design or coding choice that causes the issue, bottleneck for the limiting path, and performance debt for accumulated unresolved inefficiencies.

  • Redundant or unnecessary work: repeated calculations, scans, or queries.
  • Excessive polling, hot loops, or update frequency.
  • Missing early filtering, pruning, bounds, or short-circuiting.
  • Deficient caching: missing, poorly scoped, oversized, or incorrectly invalidated caches.
  • Resource leaks involving memory, listeners, timers, or connections.
  • Incomplete coverage of edge cases that creates pathological performance paths.

When you decide whether an existing structure can be upgraded, use the authoritative upgrade cost returned by its buildable-unit probe. Do not pre-reject the upgrade using the formula for constructing another new structure, because count-scaled new-build prices can be substantially higher than the real upgrade price. Cover this with a regression where a new structure is unaffordable but the upgrade is affordable.

In audits and issues, describe these as performance inefficiencies and anti-patterns caused by redundant work, excessive frequency, weak filtering, resource retention, or incomplete scenario coverage.

Attack policies that need the player's coastal frontier must reuse the shore subset derived from the current cached border snapshot. Random boats, island targeting, and nearby-player reconstruction must not independently reclassify the complete border with isShore during the same snapshot window.

Full-screen helper canvases that acquire a WebGL context must explicitly release that context before their canvas is removed. Removing the DOM node alone can retain the GPU context until garbage collection and repeated overlay toggles can force the browser to evict the game's older map context.
